# Nedra Backend — Платформа концептуального проектирования

Backend первого прототипа платформы комплексного концептуального проектирования для ООО «Недра» (задача NEF-28).

---

## 1. Технологический стек

- **Python**: 3.12
- **Веб-фреймворк**: FastAPI (Pydantic v2)
- **База данных**: PostgreSQL 16 (с поддержкой SQLite для локальной разработки и тестов)
- **ORM / Миграции**: SQLAlchemy 2.0 (asyncio) + Alembic
- **Объектное хранилище**: MinIO / S3 (boto3)
- **Очередь задач**: Redis 7
- **Парсинг данных**: openpyxl (`read_only=True`, `data_only=True`, `keep_vba=False`)
- **Контейнеризация**: Docker & Docker Compose
- **Тестирование**: pytest, pytest-asyncio, httpx

---

## 2. Архитектура сервиса

Проект разделен на логические слои:

```text
app/
├── api/                  # REST API роутеры и эндпоинты
│   ├── endpoints/
│   │   ├── health.py     # Проверка здоровья сервиса
│   │   ├── imports.py    # Загрузка Excel, статус, диагностический отчёт
│   │   ├── well_pads.py  # Кустовые площадки и их структура
│   │   └── wells.py      # Карточки скважин и траектории
│   └── router.py         # Объединяющий роутер API v1
├── core/                 # Конфигурация и настройки (Pydantic Settings)
├── database/             # Сессии SQLAlchemy и Base
├── models/               # SQLAlchemy модели (WellPad, Well, TrajectoryPoint, ImportTask)
├── repositories/         # Слой доступа к данным (DAO / Repositories)
├── schemas/              # Pydantic v2 схемы запросов и ответов
├── services/             # Бизнес-логика:
│   ├── excel_parser.py   # Потоковый парсинг и валидация книги Excel

│   ├── storage.py        # Интеграция с MinIO / локальным S3
│   └── task_queue.py     # Очередь задач Redis
└── workers/              # Фоновые воркеры (ImportWorker)
```

## 3. Бизнес-правила импорта и обработки профилей

1. **Структура файлов**:
   - Один Excel-файл (`.xlsx` или `.xlsm`) соответствует одной кустовой площадке.
   - Каждый лист Excel соответствует одной скважине.
   - Макросы не исполняются.
2. **Обязательные столбцы**:
   - `MD` (Измеренная глубина, м)
   - `TVD` (Истинная вертикальная глубина, м)
   - `Inclination` (Зенитный угол, град, допустимый диапазон $[0; 180^\circ]$)
   - `Azimuth` (Азимут, град, допустимый диапазон $[0; 360^\circ]$)
   - `DeviationNS` (Смещение Север-Юг, м)
   - `DeviationEW` (Смещение Восток-Запад, м)
3. **Дополнительные столбцы**:
   - `DLS`, `Radians` и любые другие лишние столбцы **не используются** для построения траектории. Ошибки формул (`#REF!`, `#NAME?`), отрицательные значения (например, отрицательный DLS) в дополнительных столбцах **не блокируют** загрузку профиля.
4. **Политика повреждённых профилей (NEF-27)**:
   - Если траектория конкретной скважины повреждена (ошибки в ячейках, `#REF!`, выход углов за диапазон):
     - Сама скважина **сохраняется** в базе данных;
     - Карточка скважины **остаётся доступной** для пользователя;
     - Устьевые координаты **сохраняются**;
     - Траектория этой скважины **целиком не загружается** (частичная загрузка строго запрещена);
     - Остальные скважины на других листах обрабатываются **независимо**;
     - Статус повреждённой траектории: `error`;
     - Сообщение: `«Траектория не загружена: ошибка в исходных данных»`.
5. **Диагностический отчёт**:
   - Для всех обнаруженных ошибок фиксируется: имя листа (`sheet`), номер строки (`row`), имя столбца (`column`), тип ошибки (`error_type`), уровень (`level`: `error` / `warning`) и описание (`message`).

## 4. Геопривязка и вопросы заказчику

### Реализованные формулы вычисления координат:

- `X = wellhead_x + DeviationEW`
- `Y = wellhead_y + DeviationNS`
- `Z = wellhead_z - TVD` (вертикальная отметка с учётом альтитуды устья)

Отдельно абсолютные координаты $X/Y$ в базе данных не хранятся, а вычисляются динамически при отдаче фронтенду через API.

> [!NOTE]
> **Вопросы и уточнения для заказчика**:
> 1. **Система координат (CRS)**: в текущей версии указано значение `"UNKNOWN"`. Требуется уточнить целевую систему координат (например, WGS 84 / UTM зоны или МСК субъектов РФ).
> 2. **Единицы измерения**: предполагаются метры для глубин и смещений, градусы для углов. Требуется подтверждение.
> 3. **Направление координатных осей**: принято стандартное геодезическое: $X$ — на восток ($DeviationEW$), $Y$ — на север ($DeviationNS$).
> 4. **Альтитуда устья**: по умолчанию установлена в 0.0 м до уточнения маркшейдерских отметок скважин.

## 5. Контракт REST API

Интерактивная документация Swagger доступна по адресу:
- `http://127.0.0.1:8000/docs`
- ReDoc: `http://127.0.0.1:8000/redoc`

### Основные эндпоинты:

| Метод | Эндпоинт | Описание |
|---|---|---|
| `GET` | `/health` | Проверка доступности сервиса |
| `POST` | `/api/v1/imports/excel` | Загрузка файла `.xlsx`/`.xlsm` (возвращает `task_id`) |
| `GET` | `/api/v1/imports/{task_id}` | Получение статуса фоновой обработки |
| `GET` | `/api/v1/imports/{task_id}/report` | Подробный диагностический отчёт об ошибках |
| `GET` | `/api/v1/well-pads` | Список кустовых площадок |
| `GET` | `/api/v1/well-pads/{id}` | Детальная структура куста и список скважин |
| `GET` | `/api/v1/wells` | Список скважин с пагинацией и фильтром по кусту |
| `GET` | `/api/v1/wells/{id}` | Карточка скважины (устье, статус профиля) |
| `PATCH` | `/api/v1/wells/{id}` | Обновление устьевых координат скважины ($X, Y, Z$) |
| `GET` | `/api/v1/wells/{id}/trajectory` | Координаты траектории с геопривязкой и пагинацией |

Параметры для `/api/v1/wells/{id}/trajectory`:
- `offset` (по умолчанию 0);
- `limit` (по умолчанию 500, макс. 10 000);
- `step` (шаг прореживания для 3D-рендеринга: 1 = все точки, 10 = каждая десятая точка).

## 6. Локальный запуск (без Docker)

В локальном режиме проект работает без обязательного наличия PostgreSQL, MinIO или Redis, используя легковесный SQLite, локальную файловую директорию для загрузок и встроенный асинхронный воркер.

### Шаги для запуска (Windows PowerShell / CMD):

```powershell
# 1. Активация виртуального окружения
.venv\Scripts\activate

# 2. Установка зависимостей
pip install -r requirements.txt

# 3. Применение миграций Alembic (по умолчанию SQLite nedra.db)
alembic upgrade head

# 4. Запуск FastAPI сервера
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Сервер доступен на: `http://127.0.0.1:8000`

---

## 7. Запуск в Docker Compose

Полный стек (FastAPI backend, независимый worker, PostgreSQL 16, Redis 7, MinIO):

```bash
docker compose up --build
```

Сервисы:
- **API**: `http://localhost:8000`
- **Swagger**: `http://localhost:8000/docs`
- **MinIO Console**: `http://localhost:9001` (логин: `minioadmin`, пароль: `minioadminpassword`)
- **PostgreSQL**: порт `5432`
- **Redis**: порт `6379`
